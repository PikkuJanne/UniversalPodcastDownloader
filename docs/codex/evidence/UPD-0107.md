## Implementation

- Preserve the existing read/plan/ShouldProcess/locked-revalidation sequence. Validate all parsed enclosure targets before archive writes. Ordinary WhatIf and legacy previews return before writer locks, media transfers, history changes or completion messages. Explicit confirmation buffers diagnostics until accepted. Preview/export guards cover failures and declined confirmation too.
- Share a built-in .NET request policy across metadata and media: absolute HTTP(S), no URL user information, controls/backslashes/unescaped ASCII whitespace, at most 32,768 URL characters. Permit private and loopback destinations. Disable automatic redirects, cookies, default credentials and preauthentication; retain platform TLS and proxy defaults. Construct fresh requests for each validated redirect, reject HTTPS downgrade and stop after five followed redirects.
- Replace the metadata web-cmdlet path with an in-memory streaming adapter capped at 8 MiB, checking declared and actual lengths. No OutFile parameter, DOM/browser parsing or compressed expansion. Decode supported text strictly; retain original feed identity across redirects and use the effective page URI for relative HTML links. HTML input is bounded and regex operations have a 250 ms timeout.
- Use explicit XmlReaderSettings with DTD prohibited, reader/document resolvers null, validation disabled, document characters capped at 8,388,608 and entity characters configured at 1,024. Streaming preflight limits depth to 64 and nodes plus attributes to 100,000 before the second bounded reader creates a DOM. Parser errors omit private content.
- Document the compatibility policy and limits in INPUT_BOUNDARIES.md. A metadata URL or its redirect can itself return unexpected audio; preview does not follow episode enclosure targets or execute media transfers. No new authentication, retry/timeout, resume, discovery, keep-awake or launcher feature.
