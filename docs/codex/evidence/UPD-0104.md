## Implementation and acceptance

- **A014:** Full feed-scoped identities prefer RSS GUID, Atom ID, then exact media URL. Request URLs and publisher strings remain exact in memory; history stores fingerprints. Discovery uses explicit exact feed aliases to reuse the established folder across title changes. Existing episode paths survive title/date/signed-URL changes. Full-snapshot contradiction checks precede mode selection; identity and case-insensitive destination collisions fail before media writes. Different feeds with equal titles remain distinct. No automatic alias inference or alias-management CLI was added.
- **A015:** Strict schema-1 state validates types, bounded sizes, relative paths, identity relationships, duplicates, versions and completion evidence. An exclusive show lock plus generation checks protects JSON updates. A brief root lock serializes discovery/initialization across first-run title changes. Owned state temporaries are flushed before atomic replacement; the prior valid generation is retained. Corrupt or contradictory primary/backup data is preserved and reported. Real child processes are killed before/after state replacement and media placement. Prepared transfer evidence permits conservative post-placement reconciliation. Real lock contention and process-death release cover both lock scopes.
- **A016:** Selected recorded media is hashed and checked against recorded size/digest before skipping. Missing files are safely downloaded to their original destinations. Changed files, including changes that preserve byte count, and unknown planned destinations are preserved and reported as conflicts/incomplete. Unknown unrelated recordings and unclaimed partials remain unchanged.

Runtime additions are bundled PowerShell helpers only: HistoryStore, HistoryIdentity and HistoryWorkflow. Existing no-overwrite media placement and bounded signature/framing validation remain. Atom ID extraction now has product regressions; its obsolete defect characterization was removed. Two parser characterizations remain (Atom date precedence and first enclosure choice). The original non-ASCII main script now has a UTF-8 BOM for PS5.1; its obsolete analyzer allowance was removed.

## Limits and handoff

- File digests prove consistency with recorded bytes, not full decoding, publisher completeness or authenticity. Same publisher ID across refreshes is treated as an edit; ambiguous publisher ID reuse cannot be inferred reliably. URL fallback changes can cause a new identity.
- Existing archives without history remain unadopted and may result in separate new downloads. Legacy inventory/adoption and rollback are UPD-0105. There is no automatic backup restoration, state migration, resume or orphan cleanup.
- An unreadable/corrupt show history or reparse output subdirectory blocks discovery under that root because alias ownership cannot safely be ruled out. Locks fail promptly when busy; UX improvements remain later work.
- File.Replace support is required. Tests cover local Windows process death, not hardware power loss, live UNC shares or privileged concurrent filesystem attackers. Privileged file symlinks and manual launcher flows remain unrun.
- Existing logs still contain legacy URLs pending UPD-0106; state introduces no raw URLs/IDs. Broader network retry/timeout, launcher/exit-code, migration and release tasks remain unimplemented. A017-A060 remain not_run.
- No merges, rebases, resets, force pushes, existing branch/issue deletion, persistent settings changes, tags/releases, purchases or deployment.
