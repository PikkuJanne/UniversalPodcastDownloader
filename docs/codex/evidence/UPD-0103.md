## Implementation and acceptance

- **A011:** Every attempt reserves a unique `.upd-<GUID>.tmp` sibling with CreateNew and keeps the exclusive writer handle open through the response and Flush(true). Caught failure closes handles and deletes only that attempt's file, after path checks. Actual process termination after the first stream write leaves one partial and no final file. Rerun starts a fresh GET, preserves the abandoned partial's hash and downloads the complete original bytes. Before-rename crashes leave only the temporary file; after-rename crashes leave only the complete final file. Existing-file skips remain unverified, pending history.
- **A012:** One media GET supplies both body and headers. Require HTTP 200 without Content-Range, reject unexpected content encodings, and compare bytes with exposed Content-Length. After closing the writer, bounded file validation rejects empty/text/unrecognized bodies and obvious signature/header truncations. Completed recognizable audio without a length succeeds; RSS/Atom enclosure estimates are advisory warnings. Integration exercises empty, HTML, JSON, XML, 206, truncated HTTP, lengthless and generic MIME responses, plus stale enclosure length. Unit tests include large ID3 artwork, BOM text, contradictory MIME, truncated RIFF and closed handles.
- **A013:** Temporary and final files share the destination directory/volume. Writer/request/validation streams close on success and failure. Two-argument File.Move preserves a competing final file. The real boundary test creates a competitor immediately before Move, verifies its exact bytes, reopens it exclusively, and confirms only the attempt's temporary file was cleaned. Existing destination and path/reparse regressions still run.

`src/MediaRequest.ps1`, `src/MediaValidation.ps1` and `src/MediaTransfer.ps1` extend the bundled helpers. The original entry points and unchanged audio remain; no runtime package is added. Page/feed requests retain safe Invoke-WebRequest. HttpClient is initialized lazily, with platform proxy/TLS defaults and automatic decompression disabled. One common adapter supports both engines.

The validation object contains `Valid`, `Category`, `Bytes`, `Verification`, `Warnings`, `DetectedFormat` and `InspectedBytes`. Accepted transfers return outcome/file/bytes/verification/signature/warnings. Validation reads at most 64 KiB, including a bounded seek beyond ID3. HTTP-length evidence is `completed_http_length_and_signature`; EOF-only evidence is `completed_eof_and_signature`. Recognized signatures cover MPEG audio, WAV, FLAC, Ogg and MP4 containers, with explicit warnings that Ogg/MP4 tracks were not decoded. This is bounded evidence, not a full decoder or authenticity check.

Main records measured bytes and warnings only after final placement. Exhausted episode failures throw after the failed summary and cannot print `[OK]`; the existing error boundary produces code 1. The full 0/2/1/130 and launcher contract remains UPD-0301. The obsolete size lookup and its two lint allowances were removed. Decisions D026-D029 record these choices.

### Failure evidence and corrections

- Before implementation, `-Suite Integration -Filter '*A012*'` failed both empty/HTML regressions in each engine: 0 passed, 2 failed, 0 skipped, 27 not_run, exit 1. Both invalid responses had been published as downloads.
- Transport exploration made 36 loopback GETs across six routes, three .NET/PowerShell adapters and both engines. PS5.1 silently returned 563 bytes for a response advertising 1,689; PS7 threw on premature EOF. Explicit byte counting closes this compatibility gap. Local Invoke-WebRequest OutFile/PassThru returned bytes in this environment, but its response also held a memory stream; the chosen adapter gives a retained exclusive file handle and streamed response headers. These probes inform design and are separate from product test counts.
- Twelve further loopback calls verified the new adapter's valid/invalid behavior on both engines. Ten chunked-framing probes confirmed valid chunks succeed and missing/malformed terminating chunks fail. PS5.1 normalizes away Content-Length when chunked framing takes precedence; the code cannot inspect a header the platform removes. See the limits below.
- The first 13-case transaction integration runs had 12 passed, 1 failed, 0 skipped, 27 not_run on each engine. The sole failure was test-harness polling of another process's open-file length. Replaced polling with a process-local debugger breakpoint immediately after an actual stream write, then flush and terminate only that owned worker. Corrected interruption and both affected A009 boundary cases passed on each engine before the final full runs. No product test hooks were added.
- Review reproduced a WAV validation hole with three declared-size regressions: 0 passed, 3 failed, 0 skipped, 234 not_run before the fix. Requiring the RIFF container to fit the stored bytes made all 39 bounded-validator checks pass on both engines. Earlier mock-scope and test-only unused-variable findings were corrected without expanding the lint baseline.

## Limits and sources

- A plausible signature plus complete HTTP/EOF transfer cannot prove the publisher supplied the whole episode, validate every frame or establish authenticity. Unsupported signatures conservatively fail. Media choice/extension and track parsing remain UPD-0205. Audio bytes are not transcoded.
- Header parsing follows each platform. In particular, PS5.1 can remove Content-Length for chunked responses; universal rejection of conflicting raw framing headers is not claimed. No HEAD request is used as a substitute for GET evidence. Default HttpClient header timeout is 100 seconds; a separate body idle policy and revised retries remain UPD-0201.
- No persistent ownership sidecar, history, adoption, resume or orphan deletion is introduced. Existing final files are preserved/skipped without durable verification. UPD-0104 must reconcile history and disk. Flush/close/same-volume rename does not promise immunity to hardware power loss or a concurrent privileged filesystem attacker.
- Existing log URL content remains for UPD-0106. No real archive/private subscription, external podcast media, manual launcher or future acceptance was exercised. A014-A060 remain not_run. No merge, history rewrite, existing branch/issue deletion, persistent policy/security setting change, release, purchase or deployment occurred.
