## Implementation and acceptance

- **A008:** Pure bundled naming helpers replace forbidden/control/format characters, normalize valid Unicode, avoid broken surrogate pairs, protect reserved device basenames including extensions/superscript digits, trim trailing dots/spaces and supply safe blanks. Raw dot/dot-dot and drive/rooted metadata are rejected. Full SHA-256 identifiers survive shortening; filenames retain an extension and omit the optional date only for a tight budget. The actual entry point succeeds with a 120-character output root and a 259-character final path. Too-small budgets fail clearly.
- **A009:** Pure canonical path construction validates ordinary drive/UNC syntax and path components before normalization, includes a separator in containment comparison, and enforces 247-character directory/259-character file limits. Disk checks inspect every existing ancestor, root and leaf for reparse points, denied access, conflicting entry kinds and case-insensitive sibling ambiguity. Root/folder creation, log creation/appends, each media attempt, final placement and owned cleanup recheck the relevant paths. An unsafe destination aborts retry processing. Actual junction and dangling-junction tests require no administrator rights. Real loopback tests reject hostile feed titles and junctions at the root, ancestor, podcast folder and media leaf, plus injected junctions before transfer and after downloaded bytes.
- **A010:** Every new feed folder and episode filename has a full identity suffix. Episode plans compare full keys ordinally and destinations case-insensitively, rejecting contradictory identity reuse and forced hash/name collisions before podcast folder/log creation. Exact duplicate entries share one plan item. Same-date/title, punctuation and case-only collisions download separately. Existing/generated and synthetic legacy files retain their bytes and timestamps. A file that appears during a media request is preserved by no-overwrite final placement.

Each transfer attempt reserves an owned `.upd-<GUID>.tmp` sibling, keeps the existing safe Invoke-WebRequest adapter, and uses two-argument File.Move. Only that attempt's temporary file is deleted on caught failure, after path checks. This is the minimum placement mechanism needed by A010; no transfer-body validation or resume/state/recovery contract is claimed. Log names use a unique run ID and CreateNew instead of overwriting a same-second log.

The distribution now includes `src/Naming.ps1` and `src/PathSafety.ps1`; the original `.ps1`/`.bat` entry points, Latest/Custom/All, configurable root and unchanged audio remain. README and decisions D021-D025 document the behavior. Analyzer discovery includes `src/`; two obsolete naming warning allowances were removed without expanding the baseline. Narrow suppressions describe pure helper naming and bounded test-only hooks.

## Limits and review

- Existing title-only archives are preserved, not automatically adopted or renamed. New names can produce separate downloads; exact URL/title changes can produce a new folder. Stable aliases/history and richer RSS/Atom identity belong to later tasks. Current existing-file skips do not verify content.
- Full-path checks conservatively refuse junctions/symlinks, including existing output-root ancestors. Reparse coverage includes mocked file attributes, real junctions and dangling junctions; privileged actual file-symbolic-link creation and live UNC shares were not tested. This is not a sandbox against a concurrent privileged filesystem attacker.
- This task does not validate HTTP framing, nonempty/audio bodies, crash recovery or stale owned temporary files. A killed process can leave a temporary sibling; later runs preserve unclaimed files. A011-A060 remain not_run. Logs retain legacy URL content pending the privacy task. Only synthetic URLs/data are in tests and shared evidence.
- No real archive/private feed, external podcast media, manual launcher, release or deployment check was used. No new runtime package, merge/rebase/reset/force-push, branch/issue deletion, persistent setting/security changes, tags/publication or purchase.

Microsoft primary references checked on 2026-10-02: [Windows naming rules](https://learn.microsoft.com/en-us/windows/win32/fileio/naming-a-file) and [path length limits](https://learn.microsoft.com/en-us/windows/win32/fileio/maximum-file-path-limitation). Compatibility of no-overwrite File.Move and filesystem attribute inspection was exercised directly in both installed Windows engines.
