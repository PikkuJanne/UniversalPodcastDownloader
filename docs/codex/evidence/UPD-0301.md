## Implemented behavior

Validate bound CLI choices before discovery or input: positive count alone implies Custom; explicit Latest/All plus any bound count fails. NonInteractive requires a nonblank explicit feed, defaults to Latest, rejects explicit Confirm and suppresses inherited confirmation in function scope. Guided feed/count input and completed-resolution reuse remain available.

`Invoke-PodcastRun` returns one schema-1 `Podcast.RunResult` with safe episode outcomes and aggregate counts. Dot-sourcing imports helpers without starting or exiting. The entry script alone emits optional PassThru and sets process status: 0 success/clean preview, 1 fatal input/setup/run failure, 2 failed/deferred/conflicting/unverified media or unresolved catalogue, 130 catchable cancellation. Preview catalogue gaps, including no accessible entries, return 2 without writes. A repeated imported run returns verified skips after checking disk evidence. Cancellation propagates through existing request/feed catches without being retried or converted to an ordinary episode failure; run locks and progress are released/restored in finally.

Routine results omit raw URLs, titles, filesystem destinations and exceptions. Plan includes only identity/source-kind, opaque request display and recorded flag. Local legacy inventory/action output is preserved in `LegacyResult`; keep it private. Explicit completed metadata adoption/rollback can succeed without counting a verified download. A later ordinary adopted-file run stays unverified/incomplete. Original media/history/resume/path/preview protection remains unchanged.

The batch launcher directly forwards %* once to quoted native engine/script paths, disables delayed expansion locally, uses a local launcher marker and preserves exact child status. The entry script retains a final Enter prompt only for an argument-free launcher call. Parameterized calls never pause; missing script produces a fixed visible fatal error. Closing-prompt failure preserves the operation status. See [CLI_RESULTS.md](../CLI_RESULTS.md), D064-D067 and primary sources S28-S29.

Native integration took 1,113.33 seconds plus 138.73 seconds for units. Intermediate development deadlines of 20 and 25 minutes were raised before the source commit after measuring both engines.
