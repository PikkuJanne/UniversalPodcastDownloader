# Initial design decisions

These are proposed project defaults for this improvement project. Record any necessary deviation with reason and evidence; do not silently replace the owner's workflow.

| ID | Decision | Rationale |
|---|---|---|
| D001 | Improve existing PowerShell tool; no rewrite. | Preserve a successful simple workflow. |
| D002 | Windows PowerShell 5.1 and PowerShell 7 on Windows. | Existing advertised compatibility remains a requirement. |
| D003 | No new runtime third-party dependencies. | Keep double-click installation approachable. Development test tools are separate. |
| D004 | One task per Codex thread; one feature branch per milestone. | Keep context bounded and GitHub continuation reliable. |
| D005 | Local active-machine testing is authoritative; CI is supplementary. | Windows behavior must be observed, not inferred from Linux helper tests. |
| D006 | Unknown legacy files are unverified, never silently removed/replaced. | Protect the current archive. |
| D007 | Local versioned JSON first; no database server. | Sufficient for modest single-user archives if locking/atomic update is correct. |
| D008 | Sequential downloads by default. | Avoid connection pressure and needless concurrency complexity. |
| D009 | Hashes help identity/integrity checking but do not prove publisher authenticity. | Do not overstate what local hashes establish. |
| D010 | Preview may read feed/HTML but does not request media or persist anything. | Clear safe preview contract. |
| D011 | CustomCount alone implies Custom; contradictory explicit Mode rejected. | Remove current surprising parameter behavior. |
| D012 | Exit codes: 0 success; 1 setup/fatal; 2 incomplete; 130 catchable cancellation. | Make automation interpret outcomes. Module helpers return objects/errors rather than exiting the host. |
| D013 | HTTP response framing and RSS enclosure length have different authority. | Metadata estimates can be stale; avoid false corruption claims. |
| D014 | Website means product/distribution content, not hosted downloading. | No server storage, hosting selection or unrelated-site changes. |
| D015 | Release tags/publication, merges/settings and paid signing remain owner-gated. | Review and explicit publication control. |

## UPD-0002 decisions (2026-10-02)

- **D016:** Dot-source the existing script to load functions without startup/main execution. Relocating startup configuration below a dot-source return preserves parameters, nine function bodies, main block and two-file distribution. No runtime module is needed yet.
- **D017:** Pin Pester 5.7.1/PSScriptAnalyzer 1.24.0 to reviewed Gallery hashes in a local developer cache. These fixed versions were exercised on both Windows engines; they are not claims about the newest releases. Setup is explicit and never runs from the downloader/test runners.
- **D018:** Use a source-context/count baseline for original lint warnings, with zero unmatched findings allowed. Exclude Write-Host for retained TUI/developer summaries. Defect characterizations are separate from future acceptance; PS5.1 BasicParsing injection is a labeled harness aid, not a production fix. See evidence/UPD-0002.md.

## UPD-0101 decisions (2026-10-02)

- **D019:** Route all existing page/feed/media calls through a small `Invoke-PodcastWebRequest` helper that always supplies `UseBasicParsing`. Keep Invoke-WebRequest, optional OutFile and existing request/error behavior. No parser-default, TLS or persistent policy mutation. This supersedes the D018 worker injection; historical evidence remains intact.
- **D020:** Wrap extraction/filtering in arrays and isolate sorting/mode selection in `Select-PodcastEpisode`, returning one array object for zero/one/many entries. Keep the existing explicit empty-feed/no-enclosure errors. This permits direct shape tests while preserving the current main loop, entry-point names and progress calculations. Broader progress UX remains UPD-0303.

## UPD-0102 decisions (2026-10-02)

- **D021:** Separate pure naming and Windows path helpers into bundled `src/Naming.ps1` and `src/PathSafety.ps1`. The original entry points remain, but installation now includes `src/`; no runtime package is added. Importing defines helpers without writes or network access.
- **D022:** New feed folders and episode names retain full SHA-256 identity suffixes. Feed identity uses the exact resolved feed URL; episodes use the existing RSS GUID then exact media URL, with a stable metadata fallback for direct helper calls. Case-sensitive full keys and case-insensitive destination maps reject contradictory identity reuse or forced hash/name collisions within the plan. Identical entries share one planned destination. Parser/Atom identity and durable alias/history policy remain assigned to later tasks. Old archives stay untouched and unadopted; new names may cause a separate download. Hashes do not prove transfer completeness or publisher authenticity.
- **D023:** Budget the complete path for both Windows engines: at most 259 UTF-16 code units for files and 247 for directories, without long-path registry changes or device namespaces. Keep full identifiers while shortening title text without splitting surrogate pairs; omit an optional date only when needed. Roots too long for minimum identifiers fail clearly. Reject raw rooted metadata and dot components before normalization; check canonical containment and all existing ancestors/targets for reparse points at writes. These checks do not provide a sandbox against a concurrent privileged local filesystem attacker.
- **D024:** Destination safety requires no-overwrite final placement even if a competing file appears during a request. Each attempt reserves a unique sibling `.upd-<GUID>.tmp`, retains Invoke-WebRequest with safe parsing, rechecks paths, and uses the two-argument File.Move. Only its owned temporary file is cleaned on caught failure, after rechecking safety. This narrow prerequisite does not complete UPD-0103: transfer framing/content validation, crash recovery and incomplete outcomes remain unimplemented/unaccepted. A killed process may leave an unclaimed temporary file, which subsequent runs preserve.
- **D025:** Give each log a unique run ID and create it without overwrite; revalidate its path before every append. Logs retain their existing content pending the assigned privacy task. No source URL or secret is placed in a filename.

## UPD-0103 decisions (2026-10-02)

- **D026:** Stream media through the built-in .NET HttpClient with ResponseHeadersRead, one GET and an exclusively held caller-owned destination stream. Keep page/feed Invoke-WebRequest with UseBasicParsing. This supersedes the media portion of D019/D024 and adds no runtime package. Loopback probes showed PS5.1 returning a short body without throwing, so compare actual bytes with the same response's Content-Length explicitly. Disable automatic decompression, request identity encoding and reject unexpected content encodings/partial responses; preserve platform proxy and TLS defaults. PS5.1 can normalize away Content-Length when chunked framing takes precedence, so raw-header conflict detection is not guaranteed. Header timeout uses the platform default; body idle/retry policy remains UPD-0201.
- **D027:** Validate the closed temporary file before no-overwrite File.Move. Return explicit outcome, bytes, signature, verification and warnings. Read at most 64 KiB, including a bounded seek past ID3 artwork; reject empty/text/unrecognized bodies and obvious header truncations. Recognizable MPEG, WAV, FLAC, Ogg and MP4 signatures are limited evidence, not full decoding or authenticity. Warn for unverified Ogg/MP4 tracks and contradictory MIME. Publisher enclosure lengths are advisory; meaningful HTTP framing lengths are authoritative. Richer media selection/extension policy remains UPD-0205.
- **D028:** Retain CreateNew, same-directory temporary files and path rechecks; keep the destination handle exclusive through transfer and flush before closing. Caught failures delete only the current attempt's owned file. Abrupt process death can leave a partial which later runs preserve and never count as complete or resume. Completion/history reconciliation belongs to UPD-0104; sidecars, adoption and resume are not introduced. Process-local debugger breakpoints test real stream interruption, before/after final rename and a competing file without product test hooks.
- **D029:** A run with exhausted episode failures throws after its failed summary and cannot print the success banner. The current entry point reports error code 1; the full 0/2/1/130 and launcher contract remains UPD-0301. Remove the obsolete post-download size lookup and its two lint allowances because the transfer now supplies measured bytes.

## UPD-0104 decisions (2026-10-02)

- **D030:** Bind each show to its original exact feed URL fingerprint and explicit alias fingerprints in bounded schema-1 history. Discover that state before deriving a new title-based folder. Reject duplicate aliases, corrupt state and reparse discovery paths; no automatic alias inference or recovery reset. Root discovery/initialization uses a brief exclusive lock, closing the simultaneous first-run/title-change race. Per-show locks then permit independent transfers. No index or new runtime dependency is needed.
- **D031:** Prefer RSS GUID, Atom ID, then exact media URL, with a source fingerprint and a feed-scoped full episode hash. Preserve recorded destinations across mutable metadata changes. Check the entire parsed snapshot for contradictory reuse before selection. Cross-refresh publisher ID reuse and fallback signed-URL changes remain inherently ambiguous. Existing archives without these records are unadopted; migration remains UPD-0105.
- **D032:** Commit prepared size/SHA-256/transfer evidence before no-overwrite final placement, then completed evidence afterward. Reruns hash disk bytes, reconcile prepared finals, safely redownload missing files and report changed/unknown destinations as conflicts. Persist only relative paths and fingerprints; request URLs stay exact in memory. Local hashes establish consistency, not authenticity. Unclaimed partials remain untouched.
- **D033:** Use held FileShare.None handles, strict versioned JSON validation, generation checks, owned flushed metadata temporaries and File.Replace with the preceding valid state as backup. Corrupt primary/backup, newer schema and unsupported atomic replacement fail without reset or fallback. Process crashes are tested; power-loss/UNC durability is not claimed. Preserve persistent lock filenames and release handles in finally. Add the UTF-8 BOM required for the existing script's non-ASCII source on PS5.1 and remove its obsolete lint allowance.

## UPD-0105 decisions (2026-10-02)

- **D034:** Inventory existing immediate show directories without writes. Original names and full modern hash suffixes are candidate hints only. Hash and inspect local signatures under a read handle; classify unknown plausible files as unverified and empty, partial, unsafe or ambiguous files as conflicts. Explicit adoption selects one episode, one exact filename and its reviewed SHA-256; recheck that digest while denying writes through the metadata commit. Title-only legacy matches stop ordinary downloads for review rather than implicitly creating a second archive.
- **D035:** Promote to schema 2 only for an explicit migration operation. Version 1 continues unchanged for ordinary archives. Schema 2 adds unverified and adopted, with adopted requiring owner-approved-local-signature evidence and an explicit transfer-completeness-unverified note. Matching adopted files remain adopted on rerun; missing or changed adopted files require another owner decision. Never promote local observations into completed-transfer evidence. No schema downgrade is allowed.
- **D036:** Explicit redownload selects one episode and allocates a separate bounded filename. Preserve all original bytes and paths, including occupied modern destinations. Save unique, flushed full-state checkpoints before each migration action; rollback restores only that checkpoint's metadata at a new generation, retains schema 2 and saves an undo checkpoint. Never remove media, unknown partials or checkpoints. Corrupt primary/backup still requires manual inspection; rollback is not automatic corruption recovery.
- **D037:** Fix the existing unused ShouldProcess boundary now because migration preview requires actual no-write behavior. Both normal WhatIf and migration Preview read feeds and local evidence without creating roots, logs, history, locks or media. Explicit actions honor WhatIf and Confirm. Broader request/XML policy and later A022 acceptance remain UPD-0107.

## UPD-0106 decisions (2026-10-02)

- **D038:** Initialize bundled, import-safe diagnostics before discovery. Try the local application-data directory, then the temporary directory, using UTF-8 without BOM, UTC timestamps, a random run ID and CreateNew. A confirmed ordinary download switches to a same-run show log and replays at most 256 recent events; retain the initial startup copy. Keep the startup sink when the show sink cannot open. Diagnostic failures report a safe standard-error notice and preserve the primary operation error. This completes the privacy work deferred by D025.
- **D039:** Render URLs as hostname plus a random request ID. Strip all user information, path, query and fragment content; retain exact request strings separately in bounded process memory. Suppress untrusted titles, publisher IDs, local paths, headers and raw exception messages in routine output. Preserve original exceptions in process and supply safe rendered ErrorDetails. Hostnames and episode fingerprints still permit correlation, so logs require owner review before sharing.
- **D040:** Export only explicitly allowed run metadata and up to 256 event timestamps, levels and fixed codes. Exclude free text and arbitrary object properties; never read logs, history, checkpoints, configuration, inventory or media into the export. Optional `-DiagnosticExportPath` uses a new file in an existing ordinary directory and never overwrites. WhatIf and legacy Preview suppress diagnostic writes, including exports. Explicit confirmation keeps diagnostics in memory until acceptance, then creates a fresh run context and discards the pre-confirmation buffer.
- **D041:** Retain startup copies, show logs and exports until owner deletion; add no automatic upload, rotation or cleanup. Keep archive state, backups and checkpoints under their separate verification/recovery policy. Existing logs may contain credentials and are never imported into new exports. Exact local legacy review objects, original exceptions inspected by a caller, input history and transcripts remain sensitive local data. Document this boundary in DIAGNOSTICS.md without claiming universal secret detection or advancing later network, configuration or launcher tasks.

## UPD-0107 decisions (2026-10-02)

- **D042:** Use one bundled HTTP(S) target and redirect policy for pages, feeds and media. Reject URL user information and non-HTTP(S)/relative targets; allow private and loopback hosts for the owner-operated local tool. Follow at most five redirects manually, validating every target and rejecting HTTPS-to-HTTP downgrade. Disable automatic redirects, cookies and default request credentials while preserving platform TLS/proxy defaults. Move metadata from Invoke-WebRequest to built-in HttpClient so the same redirect decisions apply on both engines; this supersedes the metadata transport retained in D019/D026 without adding a runtime package.
- **D043:** Cap metadata bodies at 8 MiB and parse feed XML through explicit XmlReader settings with DTD prohibited and both reader/DOM resolvers null. Limit document characters to 8,388,608, set MaxCharactersFromEntities to 1,024, and limit reader depth to 64 and reader nodes plus attributes to 100,000 before DOM allocation. Built-in character references remain subject to the document limit. Use the same settings for the DOM-loading pass. Cap direct HTML input at 8,388,608 characters and matching at 250 ms per regex operation. These limits make acceptance finite; they do not establish an exploit in the original parser defaults.
- **D044:** Retain the existing plan-before-execute ShouldProcess boundaries and verify ordinary/legacy previews through actual entry points. Validate parsed enclosure targets during planning without contacting them. WhatIf permits metadata retrieval and local reads but no planned enclosure request, media-transfer execution, persistent write, lock creation, keep-awake mutation or success banner. A supplied metadata URL or allowed redirect may still return arbitrary content through the bounded metadata reader. Revalidate state after approval under writer locks. Diagnostic/export suppression from D040 remains in force.
- **D045:** Preserve the original requested feed URL as its identity across redirects; a transport redirect does not silently add aliases or migrate history. Resolve relative HTML-discovered feed links against the effective page URI, and validate the resulting target before use. Preserve signed request path/query data separately from diagnostic display values. Keep retry/resume, pagination, richer parsing and the later launcher/result contract outside this task.

## UPD-0201 decisions (2026-10-02)

- **D046:** Extend the shared built-in HttpClient adapter with separate header and per-read idle deadlines. Use bounded async task waits plus cancellation/disposal on both engines, since .NET Framework streams may not honor a token once reading starts. Disable HttpClient's implicit timeout. Keep active progressing media free of a short total deadline; the finite retry window controls starting another attempt, not the duration of a successful transfer.
- **D047:** Retry only classified transient failures, with bounded attempts and exponential local backoff. Honor Retry-After delta seconds and HTTP dates on failures and redirects without shortening server delays. Share one retry deadline across an operation's attempts and redirects; defer when the required wait cannot fit. Inject clock and delay functions for deterministic unit tests. No background scheduler is introduced.
- **D048:** Retry metadata from empty memory and media through the complete existing transaction with a fresh owned temporary per attempt. Remove the entry point's fixed retry loop to avoid multiplied attempts. Keep untyped filesystem, validation and history failures permanent, preserve no-overwrite finalization and map transport categories to private fixed diagnostics. Resume remains UPD-0202; result/exit-code expansion remains UPD-0301.

## UPD-0202 decisions (2026-10-02)

- **D049:** Extend media attempts to resume only exact owned byte checkpoints. Require full feed/episode/destination identities, request and final URI fingerprints, a bounded strong ETag, known total and matching canonical media type/identity encoding. Restrict Range/If-Range to the recorded final URI. Validate a single complete-tail 206 before append; ignored/changed/inconsistent responses and 416 permit one fresh GET into a new file. Last-Modified alone is insufficient. This conservatively accepts fewer response forms than RFC 9110 and supersedes D048's always-fresh media retry behavior.
- **D050:** Keep resume schema 1 separate from history schemas 1/2. Flush/hash the exclusively held ReadWrite media stream before atomically replacing strict bounded sidecar JSON. Save the first nonempty chunk, then geometrically spaced checkpoints, plus forced success/caught-network-failure checkpoints. Geometric progress hashing within an attempt stays proportional to file size; recovery and forced checkpoints can rehash retained prefixes. Recovery requires exact disk length/hash; uncertain crash tails fail for review without truncation. Full-length local evidence or 416 never proves completion.
- **D051:** Preserve rejected old partials and exact sidecar snapshots. Unknown partials never become owned by filename alone. Retire the matching active sidecar after the prepared history commit and before no-overwrite placement, closing stale ownership after a rename. Keep validators and fingerprints local and exclude sidecars from diagnostic exports. No orphan cleanup, schema migration, new runtime package or new CLI flag is introduced.

## UPD-0203 decisions (2026-10-02)

- **D052:** Use one bounded source classifier and feed resolver for guided and parameter input. Retain fetched content through guided planning; recognize feed document roots and select only their direct feed items. Report valid empty feeds separately from malformed XML, unsupported roots and pages without links. Preserve exact original feed identity across redirects.
- **D053:** Resolve static HTML discovery against the effective page URI plus the first supported base href. Decode attribute entities, validate all selected discovery targets, deduplicate ordinal absolute URLs in appearance order, and retain missing-rel compatibility. Keep an explicitly limited built-in scanner rather than add a runtime HTML dependency.
- **D054:** Select a sole candidate automatically. Require a numbered guided choice for multiple candidates; parameter-supplied ambiguity fails before any candidate fetch and requests a direct -FeedUrl. Fetch only the selected candidate and refuse recursive HTML discovery. Keep display URLs privacy-safe and keep discovery within preview's metadata-only boundary.

## UPD-0204 decisions (2026-10-02)

- **D055:** Parse a bounded, explicitly documented Gregorian date subset into UTC DateTimeOffset using numeric components and fixed offsets, independent of machine culture/calendar/year windows. Preserve seven fractional digits; reject unsupported/ambiguous inputs as undated. Date-only and zone-less ISO values assume UTC as compatibility policy. RSS uses its direct pubDate; Atom published precedes updated fallback, and malformed present published remains undated. Preserve the established ID lookup so date work cannot change history identities.
- **D056:** Compare UTC ticks newest first, place dated entries before undated ones and explicitly use source positions for equal/missing dates. Apply Latest/Custom/All after ordering without mutating source records. Use the UTC calendar date for new filenames and canonical metadata comparison; document that rearranged ties may change selection.
- **D057:** Keep recorded history destinations authoritative; never rename or overwrite prior media because publication parsing changes. Retain a separate lookup-only legacy date with the earlier field priority and historical machine-local day for zoned dates. Unsupported or differently zoned historical names can still require explicit review. This hint grants no completion/adoption evidence and changes no history/resume schema.

## UPD-0205 decisions (2026-10-02)

- **D058:** Retain enclosure candidates and select the first eligible known audio in source order. Supported MIME may identify extensionless audio; generic MIME may use an audio URL path suffix. Explicit unsupported types are excluded. A generic unknown candidate is fallback only. Do not reorder an existing eligible audio URL when a later typed alternative appears; exact selected media URL identity and publisher-ID priority remain compatible.
- **D059:** Completed framing plus bounded supported byte indications determine a new file's canonical extension. Metadata disagreement yields fixed private warnings; MIME alone cannot make text or unknown binary pass. Support Layer III, WAVE, FLAC, first-packet Ogg Opus/Vorbis/Speex and M4A/structural audio handler indications. Reject observed video and ambiguous generic containers. Keep the 64 KiB read budget and bounded box traversal; no decoding, transcoding or audio-only/integrity promise.
- **D060:** Keep resume's exact provisional destination binding, then resolve a new filename with its original identity and budget before saving prepared final-path evidence. Recheck ownership/containment/no-overwrite at placement. Established record paths remain authoritative; prior failed/missing allocations with neither bytes nor digest may resolve their completed extension. Explicit separate legacy redownloads retain their allocation hash. Preserve recorded byte evidence after failures. A corrected-path preparation crash before checkpoint retirement may conservatively stop for review on the existing exact-path resume mismatch.

## UPD-0206 decisions (2026-10-02)

- **D061:** Traverse one explicitly advertised feed-level Atom next/prev-archive chain, including exact IANA HTTP relation equivalents. Validate inherited xml:base against effective response URLs and every target/hop. Same-kind feeds only; distinct continuation ambiguity stops. No HTTP Link/provider guessing or HTML recursion. Preserve original feed identity; requested/effective aliases without fragments detect cycles.
- **D062:** Bound pages at 20 by default (configurable 1-100), raw entries at 10,000 and accepted decoded metadata at 32 MiB, alongside existing per-response/parser/transport limits. Exact duplicate identities collapse in encounter order; contradictory metadata keeps the existing fatal protection. Fetch before Latest/Custom/All selection because page order does not prove date order.
- **D063:** Preserve accessible selected work while reporting cycles, bounds and page retrieval gaps as incomplete. Warn before planning and raise a fixed private error before the completed banner; preview warns without writes/media. Exhausting the supported chain does not prove coherent or complete historical coverage. Keep explicit result/launcher exit mapping in UPD-0301. FEED_PAGINATION.md records the precise supported subset and limitations.

## UPD-0301 decisions (2026-10-03)

- **D064:** Normalize selection before discovery or prompting: a positive count alone implies Custom; explicit Latest/All plus a count fails. NonInteractive requires an explicit nonblank feed, defaults to Latest without a selection, rejects explicit Confirm and suppresses inherited confirmation locally. Preserve argument-free feed/count guidance.
- **D065:** Import-safe Invoke-PodcastRun returns one schema-1 Podcast.RunResult with safe episode outcomes and aggregate counts. Only the entry script sets exit status: 0 clean success/preview, 1 fatal input/setup, 2 failed/deferred/conflicting/unverified media or unresolved catalogue, 130 catchable cancellation. Cancellation outranks fatal, which outranks incomplete; partial preview remains 2. Completed explicit legacy metadata actions can succeed without promoting local media into transfer evidence. LegacyResult retains sensitive local review/action data. PassThru emits the entry script result; the imported API always returns its result. This supersedes the main-boundary exception presentation in D039.
- **D066:** Preserve caught cancellation through the existing bounded transport/feed catches without retrying it. Dispose held run resources in finally and retain established partial/checkpoint ownership. Native Ctrl+C, process termination and power-loss behavior remain distinct; broader stop/recovery work belongs to UPD-0302.
- **D067:** Batch uses process-local DisableDelayedExpansion and UPD_LAUNCHER, quoted absolute native engine/script paths and one direct %* forwarding operation. Clear an inherited ERRORLEVEL environment shadow and preserve the child status immediately. The entry script owns the final Read-Host only when the launcher marker and original zero argument count both match; parameterized launches never pause. Missing script returns a fixed visible fatal message. Caller CMD quoting still applies; no command-string evaluation, machine-wide policy change or runtime package is added.

## UPD-0302 decisions (2026-10-03)

- **D068:** Retain exclusive OS handles for the brief output-root selection lock and the per-show writer lock. Classify bounded native sharing/lock HRESULTs separately from unavailable access, using fixed private guidance. Persistent lock contents never establish ownership; do not inspect, delete or act on a stored PID. Independent shows may transfer concurrently after root selection. A process-exit stale file is safely reopened through the same exclusive API.
- **D069:** After execution confirmation, probe write access using only a CreateNew, exclusive, DeleteOnClose file in the target or its nearest existing ordinary ancestor. Bound name allocation, never claim or remove a collided file, flush and dispose the owned probe, and recheck the actual show under its writer lock before initial history writes. Preview and declined confirmation bypass probes. Permission checks are observations and cannot reserve future access.
- **D070:** Compare quota-aware available bytes with the validated response's remaining byte count before body copying, including a validated resume tail. Enclosure sizes remain advisory. Query local/mapped ready drives; arbitrary UNC or failed capacity queries remain unknown. Unknown response length or capacity is reported explicitly and permits ordinary transfer checks; observed zero is distinct from unknown. Do not add a HEAD or second GET solely for size. Capacity may change during transfer; initial history and a failed-attempt record may exist when the response-size check rejects media.
- **D071:** On catchable cancellation, retain the owned partial and force its eligible actual-prefix checkpoint while the exclusive stream is still open. If checkpoint replacement fails, retain prior evidence and the partial for review without replacing cancellation or fabricating an offset. Unknown-length/uncheckpointed partials remain preserved without invented resume authority. Attempt every held legacy cleanup independently; preserve primary failures and typed cancellation. This supersedes D028's deletion rule for catchable cancellation only. Forced termination, physical Ctrl+C paths and power-loss durability remain separate limits.

## UPD-0303 decisions (2026-10-03)

- **D072:** Drive streamed-byte progress from the validated response's full total and actual offset, resetting these on every retry. Unknown totals remain indeterminate with measured bytes. Receiving/verifying percentages cap at 99; episode success follows verified completion history, and run 100 requires complete verified selection without catalogue gaps. No extra size-only request or URL/title/path presentation is added.
- **D073:** Animate only unredirected interactive ConsoleHost with caller preference Continue and NonInteractive absent. Use private owned activity IDs, throttle ordinary byte updates, retire the prior child before preparing another episode, and attempt each owned completion independently. Preserve global/caller preferences. Typed final progress cancellation maps an otherwise successful non-preview result to 130 while retaining committed media/counts; earlier failure/cancellation stays primary.
- **D074:** Make KeepAwake explicit, off by default and Windows-only after confirmation. Lazily compile the built-in native bridge and use a dedicated managed thread with thread affinity to acquire ES_CONTINUOUS plus ES_SYSTEM_REQUIRED and restore the exact previous flags on the same native thread. Do not request display/away mode or mutate OS power policy. Other threads' requests remain independent.
- **D075:** Treat unsupported/native power failures as fixed advisories and attempt progress, power and lock cleanup independently. Bound native worker waits; failed restoration is reported honestly. Record actual unforced Windows console rendering and native activation/restoration alongside automated instrumentation. Catchable typed cancellation does not prove physical keyboard Ctrl+C, explicit Sleep/lid behavior, physical sleep prevention, hard-kill cleanup or power-loss durability.

## UPD-0304 decisions (2026-10-03)

- **D076:** Keep saved settings opt-in and separate from archive history/resume state. Strict schema-1 JSON has exactly defined fields, bounded UTF-8/token/depth/row counts and case-insensitive unique token names. Imports and ordinary one-off/default guidance do no configuration I/O or DPAPI initialization. Treat all strings as data; no evaluation, partial malformed acceptance, automatic reset/migration or credential import.
- **D077:** Protect every full feed URL with built-in Windows DPAPI CurrentUser and fixed application/schema entropy. Create private directories/files with protected current-user-only ACLs at creation; require existing storage to match rather than silently repair it. Hold an exclusive persistent configuration lock, re-read under it and replace from an owned flushed same-directory temporary. Preserve primary typed cancellation during independent cleanup. CurrentUser protection does not defend against same-user processes/admin compromise; moving accounts/profiles requires explicitly re-saving URLs.
- **D078:** List/export/public management results allow only Name, Mode, CustomCount and FeedConfigured. Omit URLs, ciphertext, output paths and unknown properties. Create exports without overwrite in an existing ordinary directory; sanitized projections are deliberately not importable credential backups. Names still reveal subscriptions; shell input/history/transcripts and private getters remain sensitive. Failed export may retain its owned partial file and reports unknown change state.
- **D079:** Validate at most 100 selected rows plus a strict runtime override allowlist before batch execution. Run the existing single-show engine sequentially and noninteractively; release each child's resources before the next starts. Preserve successful media when another show fails; child fatal/incomplete contributes aggregate 2 without fabricating episode failures. Configuration/selection setup failure is 1, catchable cancellation is 130 with retained counts/unstarted names, and empty selection is 0. Safe child projection drops LegacyResult. Preview plans all selected shows without config/media/log/lock/export/power mutation; declined confirmation starts no children.
- **D080:** Print fixed guidance and retained numeric show/episode totals for batch setup/structural/cancellation failures even without PassThru. Establish fatal/cancelled results before secondary presentation, attempt each summary line independently and preserve the primary result if the error renderer also fails. Typed cancellation from an otherwise successful summary still yields 130. Explicit WhatIf true/false takes precedence over inherited preference at the command boundary.

## UPD-0401 decisions (2026-10-03)

- **D081:** Keep the two original entry files and 27 flat bundled helpers. Stable run/command/batch APIs return structured results; only the entry boundary sets process status. Explicitly pass one run-local transport policy/page limit through guided/direct/HTML-selected/catalogue/media/legacy paths. Imports and prior runs no longer allocate/replace caller script transport/page defaults; standalone helpers use independent factory defaults.
- **D082:** Share one rounded retry-wait implementation for redirect and operation delays. Operation owners pass their existing clock observation and attempt count, retaining zero-delay sampling, start/deadline guards, short-wakeup/oversleep rules and helper-created Deferred metadata. Injected typed/unclassified delay failures remain the original exception without added metadata. Keep metadata buffering, media streaming/resume/framing and distinct URI/identity/whitespace policies separate.
- **D083:** Clear the existing exact-URL correlation dictionary in diagnostic close finally, even without a writer or when disposal fails. Retain bounded context/events and the preview latch for deliberate post-close export. This releases those keys without claiming whole-process immutable-string erasure or protection from caller/history/transcript inspection.
- **D084:** Use one saved-run argument-name allowlist for command routing and strict batch primitive validation; retain each trust boundary's range/type/selection rules. Remove the redundant Write-Log wrapper and use Write-PodcastDiagnostic directly. Replace the empty title catch with fixed verbose fallback while preserving typed cancellation; guided metadata cancellation also propagates without a second prompt.
- **D085:** Empty the original lint warning baseline after fixing both causes. Retain only authored scoped suppressions for in-memory operations, caller-confirmed owned transactions/probes/native leases, stable helper/collection names and lookup-only legacy SHA1, plus the existing ConsoleHost WriteHost exclusion. Verify a copied runtime without developer dependencies and run the frozen full local and CI engine matrices; release packaging/help/publication acceptance stays in its later task.
