# Shared feed discovery (UPD-0203)

Both guided input and `-FeedUrl` use `Resolve-PodcastItems` and `Resolve-PodcastSource`. The source resolver returns the original input URL, effective response URI, bounded response content, classified document kind, XML/items when applicable, and all discovered candidate URLs. A supplied in-memory response can be classified without another request. The guided entry point carries its resolved feed into planning; it does not fetch that feed again.

A direct feed is recognized from its actual XML document element: an unnamespaced `rss`, or `feed` in `http://www.w3.org/2005/Atom`. Item selection stays under that root. Names inside a comment, script, text, or nested unrelated XML do not establish a feed. XML still uses the existing DTD-prohibited, resolver-disabled, character/depth/node limits. This is format classification, not complete RSS/Atom schema validation. Empty recognized feeds have a distinct fixed diagnostic; malformed/over-limit XML, unsupported XML roots and pages without feed links also have distinct messages.

HTML discovery uses a static scanner bounded to 8,388,608 characters, 100,000 tokens and 250 ms per regex operation, without a browser DOM or script execution. It reads RSS/Atom media types on `link` elements with `rel=alternate`; missing `rel` remains accepted for compatibility. Attribute names/order/case, spaces around `=`, quoted/unquoted values and HTML character references are supported. Surrounding ASCII whitespace is trimmed from URI references; embedded whitespace is refused. Comments, template content, script/style and other raw text elements, noscript and plaintext do not supply feed links. Unterminated attributes/tags do not turn nested text into links. It resolves candidates against the effective page response URI, applying the first supported `base href` and ignoring later bases. Relative and protocol-relative links are checked through the same HTTP(S)/credential policy as direct requests. Unsafe base/candidate values fail closed. It deduplicates normalized absolute URLs with ordinal comparison while preserving first appearance; path/query case and query ordering remain significant.

For one candidate, both workflows select it automatically. For several candidates, guided input displays numbered privacy-safe URL labels and requires a valid number. A parameter-supplied page URL fails with `Multiple feed links were found. Supply a direct feed URL with -FeedUrl.` before requesting any candidate. The user can copy a direct feed URL from the page and run again. No first-candidate or trial-download guess is made. The selected URL must return a feed: discovery does not recursively crawl pages.

Direct feed identity remains the exact original request string across redirects. For a page, archive identity uses the selected discovered feed URL, retaining that URL across its own redirects. Effective/base URIs support discovery and do not silently replace established history identities.

Metadata may be fetched during preview. Planned enclosures, archive directories, diagnostic files/exports, locks and state are still behind the existing preview/confirmation boundary. Discovery adds no runtime package, parser dependency or CLI parameter. Date ordering, audio selection and bounded pagination are implemented separately in [PUBLICATION_DATES.md](PUBLICATION_DATES.md), [AUDIO_FORMATS.md](AUDIO_FORMATS.md) and [FEED_PAGINATION.md](FEED_PAGINATION.md). Process exit classifications remain UPD-0301.

This scanner supports static discovery markup, not every browser HTML error-recovery rule, JavaScript-generated subscription links, HTTP `Link` discovery, RSS 1.0/RDF, arbitrary XML namespaces or provider-specific scraping. Test evidence records the exact supported cases and limits.
